# Clad marketing site

Astro static site for Clad (field software for telecom, utility, and infrastructure contractors).
Not a Propel project.

## Conventions
- Design source of truth is the Figma file (Clad design system). Read it through the Figma MCP; do not invent colors, type, or spacing.
- Tokens live in `src/styles/tokens.css` as CSS custom properties, generated from Figma variables. Components use tokens, never raw values.
- Page grid: one column for every section. `--rail` (144px at 1440 for a 1152px column, min 144px on desktop, the gutter on phones) is the header's logo divider and the left/right edge of `.container` and `.container-wide` (now identical). Vertical rules must sit on the rail. The header's Log in / Get demo buttons deliberately break the grid and sit at the window's right edge (gutter).
- Section typography: use `.t-label` (mono eyebrow) and `.t-title` (section headline) from global.css; the product story and Who it's for share them so they always match.
- Product colors, used everywhere a product appears (hero tab, story label swatch, active feature rule; story panels are a neutral light gray): Billing = International Orange, Project Management = Cobalt, Locates = Stoplight. Hero tabs run in story order: Billing, Project Management, Locates.
- One Astro component per page section, in `src/components/`, composed in `src/pages/index.astro` top to bottom. Current order: Header, Hero, LogoBand, CtaBanner, ProductStory, Testimonial, Audiences (use cases + case studies, tabbed by audience), Changelog (dark band), Faq, Footer. Additional Tools was cut on 2026-09-25; the project board mock is no longer in the story.
- Copy marked DRAFT in component comments (Asset Owner features) is Claude's placeholder pending Jason/Jocelyn. The Asset Owners quote is a bracketed placeholder; never replace it with an invented quote or name. The sample customer name in the story UIs is Intrepid (a real customer logo on the page), replacing Acme / Big TelCo. Story headlines/subheads/features are Jason's and Jocelyn's; the Locates scene data is Claude's.
- Scroll animations are vanilla JS in `src/scripts/`, scroll-scrubbed (progress 0..1 per pinned section) using the actor/keyframe pattern from `reference/prototypes/build_e.py`. Respect `prefers-reduced-motion`.
- `ProductStory.astro`, `src/scripts/story.js` (engine) and `src/scripts/story.config.js` (keyframes) are GENERATED by `reference/gen_story.py` (run `python3 reference/gen_story.py` from anywhere); styles come from `reference/story.css`. Edit those, not the outputs. Layout (2026-10-09): each scene pins a two-column frame centered under the nav; left has label, headline, subhead and three stacked features (30% opacity, the current step at 100%; clicking one scrolls to `REST` in gen_story.py, where that step has finished animating, never mid-transition), right has the stage. Locates also has a Learn more / Try it out button pair under the subhead (header .btn styles; Try it out has no destination yet, `#try-locates`). Scroll progress splits into three steps at 0 / .36 / .69, and each step animates one thing. Every stage is the same light gray panel (#f4f4f2): a 16:10 content box plus 25px padding top and bottom, so 50px taller than 16:10. Scenes, in order: Billing (three update cards cascade in diagonally, no list header -> each card flies into the invoice line it becomes -> QuickBooks sync chip), Project Management (B&W blueprint -> its three runs draw in orange/cobalt/green and labels cascade -> the weekly report draws one series per run in the same colors, lines only, no legend -> dotted forecast), Locates (AI-drafted ticket types itself and submits -> your tickets clear/renew -> subcontractor tickets roll in). Every UI shows three line items and is coded HTML/SVG; there are no images in the story. Actors are positioned by center (x, y in % of the stage), width w, scale s. Copy follows Jason's Q3 homepage doc; the blueprint is traced from Jocelyn's start/end frames in `reference/figma/blueprint-*.png` (basemap cleaned by `blueprint-clean.py`, vectorized with potrace into `blueprint-map.svg`). Original Clad screenshots are in `reference/figma/story-screenshots/` for reference only.
- Product pages (first pass 2026-10-13, no Figma frame yet): `/locates` is `src/pages/locates.astro` with sections in `src/components/locates/` (sub-nav + hero, features, states map, closing CTA) plus the shared Header and Footer (no changelog on product pages). The features section reuses the product story's list and gray panel, but clicks switch panels instead of scroll scrubbing; each panel's UI plays once (CSS animations) when picked. Copy is from the old withclad.com/locates/overview page; Schedule Tickets has no copy (bracketed placeholder) and its UI, and all panel sample data, are Claude's. Supported states on the map are read off the old page's map; confirm before launch. Map paths are `src/data/us-states.json`, built by `reference/gen_us_map.mjs`. `EmailForm.astro` is the light email + Get started form (not wired to anything). Nav links use `/#section` so they work from any page.
- Hero has no load animation (tried and removed 2026-09-23); motion budget goes to the product story.
- Who it's for (Audiences), per Jocelyn's frame (2026-10-12): centered label, tabs and subline, features as open rows between light hairlines with black icons on the left, one dark Tar proof card on the right with the logo, headline and link grouped at the bottom (Intrepid case study for Contractors, quote placeholder for Asset Owners).
- Footer stripes collapse instantly when armed and only the reveal animates (1.6s ease-in-out, .25s beat, .11s cascade).
- Node is installed via Homebrew at `/opt/homebrew/bin`; run `npm run dev` for the dev server on port 4321.
